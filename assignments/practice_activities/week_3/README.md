## How publishing differs from the other topics

Notebooks are published as before: `site_config.json` lists the student and solution files and `tools/build_site.py` writes Colab / GitHub links into `docs/index.html`.

The HTML page cannot be opened from GitHub's file view (GitHub shows source, not a rendered page) and it is not a notebook, so it is published a different way: the config item uses a `"page"` key instead of `"student"`/`"solution"`, and `build_site.py` **copies the file into `docs/week_3/pandas.html`** so GitHub Pages serves it, then renders an *Interactive → Open page* button. The source stays in `assignments/practice_activities/week_3/joining_and_merging/`; `page_dest` pins the served address to `/week_3/pandas.html`.

```jsonc
{ "title": "Pandas in motion — interactive joins, concat, and reshaping (Learn + Quiz)",
  "page":  "assignments/practice_activities/week_3/joining_and_merging/pandas.html",
  "page_dest": "week_3/pandas.html" }
```

Consequences:

- **Edit `pandas.html` here, never in `docs/`.** Re-run `python3 tools/build_site.py` to refresh the served copy, then commit both.
- `"publish": false` + `"placeholder"` hides the page from the site index like any other item, but the copy in `docs/` is still reachable by URL; delete `docs/week_3/pandas.html` as well if it must be unreachable.
- The notebooks are generated by `tools/build_week3_joins.py` (see the docstring). Edit the generator, not the `.ipynb` files, and re-run it; it writes the student and solution copies and executes the solution with the Anaconda kernel.


## How to test the website

### A. Locally, before pushing (about 5 minutes)

Open the file directly in a browser (`open assignments/practice_activities/week_3/joining_and_merging/pandas.html` on macOS). Everything is self-contained, so no server is needed.

1. **Learn tab loads** with *Inner join* selected, two input tables on the left, an empty result on the right, and the pandas call in the *Python syntax* panel.
2. **Play / Step / Back / Restart.** Press *Play*; rows should fly from the inputs into the result one at a time, the status line should explain each row, and the progress bar should reach the end. *Step →* and *← Back* move one row; *Restart* clears the result. Keyboard `→`, `←`, `Space`, `R` do the same.
3. **Hover to trace.** Hover a result row: its source rows highlight. Click a result row: the animation jumps to that step.
4. **Every technique plays through.** Go down the *Technique* dropdown (20 entries, from *Inner join* to *Crosstab: counts*) and press *Play* on each. Watch for `NA` cells in left/right/outer joins, 6 rows in *Cross join*, 4 rows in *Duplicate matches*, and the `_merge` column in *Audit + validate*.
5. **Deep links.** Append `#left-join`, `#full-outer-join`, `#pivot-long-wide` to the URL and reload; the matching technique should be selected. The address bar should update when you change technique.
6. **Edit data.** Expand *Edit or generate input data* under *Left join*. Add the line `1,65` to `grades` and *Apply changes*: the result should now have no `NA`. Enter a malformed row (wrong number of cells) and confirm a red message appears instead of a broken table. *Reset to sample data* restores the originals. *Generate 3 rows* adds plausible rows (fresh IDs, names, scores).
7. **Errors are surfaced, not swallowed.** Under *Pivot: long → wide*, add the row `Ava,E1,100` and apply: the status line should show a `ValueError` about duplicate entries. Under *Audit + validate*, add a second row with `student_id` 2 to `students`: a `MergeError` should appear.
8. **Setup code is runnable.** Open *Sample data setup — copy before running the code*, paste it and the call into a notebook cell, run it, and compare with the page. The notebook's Section 9 does exactly this.
9. **Quiz tab.** Switch modes with the three buttons. *Write the call*: choose DataFrames and type code; check that a correct answer (e.g. `students.merge(grades, on="student_id", how="left")` for *Left join*) scores, that single quotes and extra spaces are accepted, and that a wrong answer shows the reference code with a *Watch this technique* link that opens the Learn tab at that demo. *Pick the technique* and *What question is answered?* each show four radio options; *Show hint* gives a hint without scoring. The score at top right increments.
10. **Colour coding.** In every demo the LEFT input table has a blue caption/border and blue-shaded columns, the RIGHT table orange; key columns are green (⚷); result columns are shaded by the table they came from, with a thick rule where the source changes; columns the operation created (`_merge`, `E1`/`E2` after a pivot, a mean) are yellow; `NA` cells are pink. A legend sits under the *Result* heading and in the quiz. *Concat: add rows* shades result **rows** by source instead. Switch the theme to Dark and confirm the tints are still readable; hover/active row highlights must still show through.
11. **Theme and width.** The *Theme* button cycles Auto / Light / Dark. Narrow the window below ~700 px: the two panels should stack and tables should scroll horizontally rather than overflow the page.

### B. Cross-check the page's engine against pandas

The page imitates pandas with its own JavaScript engine (checked against pandas 2.2.3 on the sample data). The solution notebook is the ground truth for every technique: Sections 2–7 run the *same* sample tables through pandas. To re-verify after editing the page:

1. Run `python3 tools/build_week3_joins.py` (or open the solution notebook and *Run all*).
2. For each technique, compare the notebook output with the page's result table: same rows, same order, same `NA` cells, `80.0`-style floats where a `NaN` entered an integer column.
3. If they differ, pandas is right; fix the engine in `pandas.html` (functions `merge`, `anti`, `cross`, `concatRows`, `concatCols`, `pivotLike`, `groupby`, …) and re-run the checklist above.

### C. After pushing (about 2 minutes)

1. Open <https://gato365.github.io/gsb5544_instructor_learn_prep/> — a **Week 3** heading with an *Interactive* card, a *Topic 3.1* card, and *PA 3.1* / *PA 3.2* cards should be there.
2. *Open page* must load the interactive page at `/week_3/pandas.html` (a 404 means `docs/week_3/pandas.html` was not committed — re-run `build_site.py` and commit `docs/`).
